# AGENTS.md

Fire Space Academy is a single-page, Spanish-language roleplay site (dark red / jet black / gold palette, emerald only for "accepted" states). Built on TanStack Start, deployed on Netlify.

## Hard content rules (from the owner)

- All narrative copy must come from the official lore. Do not invent lore, places (no gardens, greenhouses, nature), or students.
- The student directory reads only from `data/estudiantes.json`. Never add fictional students. Sakuya is the only official test student.
- "Edad Off" must never be shown publicly (only in the admin-only application view).
- Pending applications show only the name publicly. Full details require the admin code.
- Applicants may only choose Artística, Académica, or Deportiva. Personal is reserved for Rango 4.

## Architecture

```
data/
  estudiantes.json   # Owner-edited student registry (has _LEEME + _PLANTILLA). Read only on the server.
  destacados.json    # Owner-edited featured figures (Kim Taehyung, Sangwon).
  link.json          # WhatsApp link. Server-only: returned only for accepted codes.
db/
  schema.ts          # `solicitudes` table (applications).
  index.ts           # Drizzle client (drizzle-orm/netlify-db).
netlify/database/migrations/  # Generated by drizzle-kit. Never edit applied migrations.
src/lib/academia.ts            # Shared types, constants, name normalisation, points/image helpers.
src/lib/academia.functions.ts  # All server functions: data, applications, admin actions, Oficina lookup.
src/components/fs/             # One file per page section (hero, historia, inteligencias, rangos, zonas,
                               # destacados, directorio, expediente, intruders, admisiones, oficina, pie).
src/routes/index.tsx           # Composes the page; loader fetches academy data + public applications.
public/img/                    # corredor.png (hero), estudiantes/ (owner-uploaded portraits).
```

## Non-obvious decisions

- The admin code (`FS-2110`, overridable with the `FS_ADMIN_CODE` env var) and applicant codes are checked only on the server. Public responses never include codes or Edad Off.
- Applicant codes are `FS-` + 4 digits, unique via a DB constraint with retry. They must not collide with the admin code or with `codigo` values in `estudiantes.json`.
- Name uniqueness uses `claveNombre()` (lowercase, accents stripped) against both the JSON registry and the DB (`nombre_clave` unique column). The client does a live check, and the server enforces it.
- Rejected applications are deleted lazily (on list, submit, or Oficina lookup) once `rechazada_en` is older than 24h. There is no scheduled function.
- Applicants can delete their own application with their code. The admin code also works for deletion.
- The Oficina checks DB applications first, then `estudiantes.json` entries that have a `codigo`.
- Accepted applications are not auto-added to the directory. The owner adds students by hand in `estudiantes.json`.
- Local images go through `/.netlify/images` via `urlImagen()`. External URLs are used as-is.

## Conventions

- Spanish identifiers and copy in the `fs` components. Use theme tokens (`text-gold`, `bg-blood`, `bg-jet`, `border-gold/…`) and the helper classes in `src/styles.css` (`fs-panel`, `fs-frame`, `fs-eyebrow`, `fs-title`, `fs-label`, `fs-redacted`, `fs-reveal`).
- Fonts: Cinzel (display), EB Garamond (body), IM Fell English (newspaper), Special Elite (typewriter).
- Server functions return `{ ok: true, ... } | { ok: false, error }` for expected failures.
- Schema change: edit `db/schema.ts`, then run `npx drizzle-kit generate --name <verb_description>`.
